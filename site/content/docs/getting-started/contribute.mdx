This page is for contributors working on Chassis CSS itself. If you only want to use Chassis in your own project, [Installation]([[docsref:/getting-started/installation]]) and [Clone and Customize]([[docsref:/getting-started/clone-customize]]) cover what you need.

## Tooling setup

Local development depends on Node.js and [pnpm](https://pnpm.io/); the documentation site is built with [Astro](https://astro.build/).

1. **Install Node.js 22 or later.** [nodejs.org](https://nodejs.org/) ships installers; Volta and nvm are good options if you manage multiple Node versions.
2. **Install pnpm.** The version is pinned in the `packageManager` field of `package.json`; `corepack enable` installs and uses it. See [pnpm.io/installation](https://pnpm.io/installation) for other ways.
3. **Fork and clone the repository.**

   ```sh
   git clone https://github.com/chassis-ui/css.git
   cd css
   pnpm install
   ```

   `pnpm install` installs the dependencies of the framework and the documentation site, including the `@chassis-ui/tokens` and `@chassis-ui/icons` packages from npm.

When the install finishes, the scripts documented below are ready to run.

## pnpm scripts

The full list of scripts lives in [`package.json`]([[config:repo]]/blob/main/package.json). The ones you'll use most often:

<CxTable>
| Command | What it does |
| --- | --- |
| `pnpm dev` | Compiles CSS and JS in watch mode and starts the docs site dev server. The fastest feedback loop for working on the framework or the docs. |
| `pnpm dist` | Produces the full `dist/` and `js/dist/` output — compiled, prefixed, and minified CSS and JS, the Tailwind entry, and the type declarations. Both folders are committed; commit the rebuilt files with the source change. |
| `pnpm test` | Lints CSS, JS, and the docs, builds the distribution, runs the Sass and JS unit tests, builds the docs site, and lints the built docs. |
| `pnpm verify` | Rebuilds `dist/` and `js/dist/` and fails when the result differs from what is committed. CI runs it. |
| `pnpm css:compile` | Compiles SCSS to CSS using Dart Sass with source maps. |
| `pnpm css:test` | Runs the Sass test suite (`scss/tests/`). |
| `pnpm js:test` | Runs the unit tests for the JS plugins with [Vitest](https://vitest.dev/) in browser mode. |
| `pnpm js:typecheck` | Type-checks the TypeScript sources of the JS plugins. |
| `pnpm site:build` | Builds the static docs site for production. |
</CxTable>

Run `pnpm run` with no arguments to see every available script.

## Sass

Chassis CSS uses [Dart Sass](https://sass-lang.com/dart-sass/). The output is post-processed with Autoprefixer and minified with [Lightning CSS](https://lightningcss.dev/).

[Sass deprecation warnings](https://sass-lang.com/documentation/breaking-changes/) appear during compile when a transitional Sass syntax is used. They don't block the build. The project [tracks the long-term cleanup work]([[config:repo]]/issues) — silencing the warnings in your local config is fine in the meantime.

## Autoprefixer

Compiled CSS is post-processed with [Autoprefixer](https://github.com/postcss/autoprefixer) using the targets defined in [`.browserslistrc`]([[config:repo]]/blob/main/.browserslistrc). The build invokes Autoprefixer automatically; if you compile Chassis from source in your own pipeline, run Autoprefixer on the output to match the support matrix in our distribution build.

## RTL

Chassis CSS supports RTL through CSS logical properties used throughout the framework. Setting `dir="rtl"` on the `<html>` element is sufficient for most components. A small number of components — carousel controls, breadcrumb dividers, menu placement — use explicit `[dir="rtl"]` selector overrides where the CSS value itself needs to change, not just its direction. See [RTL]([[docsref:/core-concepts/rtl]]) for details.

## Documentation site

The documentation is a static [Astro](https://astro.build/) site under `site/`. To run it locally:

1. Run through the [tooling setup](#tooling-setup) above so dependencies are installed.
2. From the project root, run `pnpm dev`.
3. Open [`http://localhost:4323/css/`](http://localhost:4323/css/) in your browser. Edits to the docs MDX files hot-reload automatically.

The site source is in `site/`; content lives under `site/content/docs/`. Astro's [documentation](https://docs.astro.build/) covers the rendering side of the stack.

## Troubleshooting

If a fresh clone refuses to install or build cleanly:

```sh
rm -rf node_modules
pnpm install
```

If `pnpm verify` fails after a change, a file in `dist/` or `js/dist/` is out of date. Rebuild with `pnpm dist` and commit the changed files.

For anything that survives those resets, [open an issue]([[config:repo]]/issues/new/choose) with the failing command and your environment (Node version, pnpm version, OS).
