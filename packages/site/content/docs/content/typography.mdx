HTML elements receive typographic styles automatically; class-based utilities cover sizes, weights, families, and context-specific presets. For text alignment, transformation, decoration, and truncation utilities, see the [text utilities]([[docsref:/utilities/text]]) page.

## Global settings

Body text defaults to the `ui` font family at the medium size and medium line-height. Headings take the family and weight of the `heading` role group, and each level from `h1` down to `h6` its own size and line-height. All of these defaults are driven by design tokens and can be overridden via CSS custom properties or Sass variables — see the [Design Tokens]([[docsref:/core-concepts/design-tokens]]) page for details.

## Headings

All six HTML heading elements are styled by default with size and line-height pairs sourced from typography design tokens.

<Example code={`<p class="font-h1">h1. Chassis CSS</p>
  <p class="font-h2">h2. Chassis CSS</p>
  <p class="font-h3">h3. Chassis CSS</p>
  <p class="font-h4">h4. Chassis CSS</p>
  <p class="font-h5">h5. Chassis CSS</p>
  <p class="font-h6">h6. Chassis CSS</p>`}
  customMarkup={`<h1>h1. Chassis CSS</h1>
  <h2>h2. Chassis CSS</h2>
  <h3>h3. Chassis CSS</h3>
  <h4>h4. Chassis CSS</h4>
  <h5>h5. Chassis CSS</h5>
  <h6>h6. Chassis CSS</h6>`} />


### Heading classes

Apply `.font-h1` through `.font-h6` to any element to match the visual style of the corresponding heading without changing the document outline.

<Example code={`<p class="font-h1">h1. Chassis CSS</p>
<p class="font-h2">h2. Chassis CSS</p>
<p class="font-h3">h3. Chassis CSS</p>
<p class="font-h4">h4. Chassis CSS</p>
<p class="font-h5">h5. Chassis CSS</p>
<p class="font-h6">h6. Chassis CSS</p>`} />

<Callout type="warning">
`.h1` through `.h6` are deprecated in v0.10.0 and still style an element like `.font-h1` through `.font-h6`. They are removed in the next breaking release; replace each with its `.font-h*` class.
</Callout>

### Heading with subtext

Nest a `<small>` element with `.fg-subtle` inside a heading to render a secondary label at reduced prominence.

<Example code={`<h3>
    An example heading
    <small class="fg-subtle">With faded secondary text</small>
  </h3>`} />

## Font size

Font size utilities set both `font-size` and a paired `line-height` in a single class. The 10-step scale is the one of the `ui` family and maps directly to Figma text style names, keeping class names consistent with what designers specify in handoff. Combined with `.font-prose`, the same classes take the sizes of the `prose` family (see [Prose font](#prose-font)).

### Available sizes

<Example code={`<p class="font-5xl">.font-5xl</p>
<p class="font-4xl">.font-4xl</p>
<p class="font-3xl">.font-3xl</p>
<p class="font-2xl">.font-2xl</p>
<p class="font-xl">.font-xl</p>
<p class="font-lg">.font-lg</p>
<p class="font-md">.font-md</p>
<p class="font-sm">.font-sm</p>
<p class="font-xs">.font-xs</p>
<p class="font-2xs">.font-2xs</p>`} />

- **Figma alignment**: class names match the Figma text style names for the size scale, removing the translation step between design and code.
- **Design token sync**: each size references a design token, so a token change propagates to every use automatically.
- **Paired line height**: each class sets a matching `line-height` alongside `font-size`, removing the need for a separate line-height override when changing size.

### Fluid sizes

Font size classes use `clamp()` for fluid scaling by default — each value transitions smoothly between a minimum and maximum as the viewport width changes, with no extra class required. See [Fluid sizing]([[docsref:/core-concepts/fluid-sizing]]) for the toggle, configuration variables, and the Sass mixin API.

### Responsive sizes

Responsive classes are a separate mechanism for cases where continuous fluid scaling doesn't satisfy the design — for example, when a layout requires a specific size locked to a specific breakpoint rather than a smooth transition between them. Enable responsive classes with `$enable-responsive-font-sizes` (off by default).

These classes follow a mobile-first approach: `font-{size}` sets the base (applied at all widths) and `{breakpoint}:font-{size}` overrides at a specific breakpoint and wider. Available breakpoints are `sm`, `md`, `lg`, `xl`, and `2xl`. Classes can be stacked for progressive scaling.

<Example code={`<p class="font-sm md:font-lg lg:font-2xl xl:font-4xl">
  Progressively larger text
</p>`} />

## Font weight

Four weight utilities map to the token-defined weights of the `ui` family, with names that match the Figma text style weight names. Combined with `.font-prose`, `.font-display` or `.font-code`, they take the weights of that family.

<Example code={`<p class="font-mass">Mass text.</p>
<p class="font-strong">Strong text.</p>
<p class="font-normal">Normal text.</p>
<p class="font-elegant">Elegant text.</p>`} />

<Callout type="info">
Chassis uses semantic weight names (`mass`, `strong`, `normal`, `elegant`) rather than conventional names like `light`, `regular`, or `bold`. Conventional names map inconsistently across font families and brand tokens. With semantic naming, `strong` may map to `600` for one brand or font and `700` for another.
</Callout>

## Inline text elements

Common inline HTML5 elements receive default styles for semantic markup.

<Example code={`<p>You can use the mark tag to <mark>highlight</mark> text.</p>
<p>This <del>example text</del> is meant to be treated as deleted.</p>
<p>This <s>example text</s> is meant to be treated as no longer accurate.</p>
<p>This <ins>example text</ins> is meant to be treated as an addition to the document.</p>
<p>This <u>example text</u> rendered as underlined.</p>
<p>This <small>example text</small> is meant to be treated as fine print.</p>
<p>This <strong>example text</strong> rendered as bold text.</p>
<p>This <em>example text</em> rendered as italic text.</p>`} />

### Semantic usage

Elements and their intended roles:

- `<mark>`: highlights text for reference or notation purposes.
- `<small>`: represents side-comments or fine print, such as legal text.
- `<del>`: marks text that has been removed from the document.
- `<ins>`: marks text that has been added to the document.
- `<s>`: indicates text that is no longer relevant or accurate.
- `<u>`: denotes text with a non-textual annotation.

For purely stylistic purposes, the following classes apply the same visual treatment without the semantic element:

- `.text-mark`: applies highlight styles matching `<mark>`.
- `.text-sm`: applies the reduced font size matching `<small>`.
- `.text-decoration-underline`: matches `<u>` styling.
- `.text-decoration-line-through`: matches `<s>` styling.

## Abbreviations

The `<abbr>` element exposes the expanded form on hover via its `title` attribute. Add `.font-initials` to render uppercase initials at a reduced font size.

<Example code={`<p><abbr title="attribute">attr</abbr></p>
<p><abbr title="HyperText Markup Language" class="font-initials">html</abbr></p>`} />

## Blockquotes

Wrap quoted content in `<blockquote class="blockquote">` to apply the blockquote typographic treatment.

<Example code={`<blockquote class="blockquote">
    <p>A well-known quote, contained in a blockquote element.</p>
  </blockquote>`} />

### Attribution

Wrap the `<blockquote>` in a `<figure>` and use `<figcaption class="attribution">` to attribute the source. The `.attribution` class prepends an em dash automatically.

<Example code={`<figure>
    <blockquote class="blockquote">
      <p>A well-known quote, contained in a blockquote element.</p>
    </blockquote>
    <figcaption class="attribution">
      Someone famous in <cite title="Source Title">Source Title</cite>
    </figcaption>
  </figure>`} />

### Alignment

Apply text alignment utilities to the wrapping `<figure>` to reposition the blockquote and its attribution together.

<Example code={`<figure class="text-center">
    <blockquote class="blockquote">
      <p>A well-known quote, contained in a blockquote element.</p>
    </blockquote>
    <figcaption class="attribution">
      Someone famous in <cite title="Source Title">Source Title</cite>
    </figcaption>
  </figure>`} />

<Example code={`<figure class="text-end">
    <blockquote class="blockquote">
      <p>A well-known quote, contained in a blockquote element.</p>
    </blockquote>
    <figcaption class="attribution">
      Someone famous in <cite title="Source Title">Source Title</cite>
    </figcaption>
  </figure>`} />

## Lists

Chassis adds two list modifier classes for common layout needs; nested lists are unaffected.

### Bulletless

Remove default markers and left margin by adding `.bulletless`. The class applies only to immediate children, so nested lists retain their default appearance.

<Example code={`<ul class="bulletless">
    <li>This is a list.</li>
    <li>It appears completely unstyled.</li>
    <li>Structurally, it's still a list.</li>
    <li>However, this style only applies to immediate child elements.</li>
    <li>Nested lists:
      <ul>
        <li>are unaffected by this style</li>
        <li>will still show a bullet</li>
        <li>and have appropriate left margin</li>
      </ul>
    </li>
    <li>This may still come in handy in some situations.</li>
  </ul>`} />

### Inline

Display list items inline by adding `.inline`.

<Example code={`<ul class="inline">
    <li>This is a list item.</li>
    <li>And another one.</li>
    <li>But they're displayed inline.</li>
  </ul>`} />

### Description lists

Align terms and descriptions horizontally with the [grid]([[docsref:/layout/grid]]): `.grid` on the `<dl>` and a span class on each term and description. Add `.text-truncate` to truncate long terms with an ellipsis.

<Example code={`<dl class="grid row-gap-0">
    <dt class="col-span-full sm:col-span-3">Description lists</dt>
    <dd class="col-span-full sm:col-span-9">A description list is perfect for defining terms.</dd>

    <dt class="col-span-full sm:col-span-3">Term</dt>
    <dd class="col-span-full sm:col-span-9">
      <p>Definition for the term.</p>
      <p>And some more placeholder definition text.</p>
    </dd>

    <dt class="col-span-full sm:col-span-3">Another term</dt>
    <dd class="col-span-full sm:col-span-9">This definition is short, so no extra paragraphs or anything.</dd>

    <dt class="col-span-full sm:col-span-3 text-truncate">Truncated term is truncated</dt>
    <dd class="col-span-full sm:col-span-9">This can be useful when space is tight. Adds an ellipsis at the end.</dd>

    <dt class="col-span-full sm:col-span-3">Nesting</dt>
    <dd class="col-span-full sm:col-span-9">
      <dl class="grid row-gap-0">
        <dt class="col-span-full sm:col-span-4">Nested definition list</dt>
        <dd class="col-span-full sm:col-span-8">I heard you like definition lists. Let me put a definition list inside your definition list.</dd>
      </dl>
    </dd>
  </dl>`} />

## Font families

Chassis names its font families by their job, never by their typeface: the typeface of each comes from the brand's design tokens.

<CxTable>
| Family | Job | Scale | Class |
| --- | --- | --- | --- |
| `ui` | Components and the body of the page | 10 sizes, 4 weights | `.font-ui` |
| `prose` | Reading content: articles, posts, long-form text | 10 sizes, 4 weights | `.font-prose` |
| `display` | The roles a brand sets in a display typeface: headings, jumbo, hero | 4 weights, no sizes | `.font-display` |
| `code` | Code snippets and technical text | 3 sizes, 2 weights | `.font-code` |
| `icon` | The icon font | — | — |
</CxTable>

`display` has no sizes of its own: it is reached through the text roles that use it, which hold their own sizes. `prose` has a full scale because reading content is set at many sizes. In the default tokens `prose` is the typeface of `ui`, with the same sizes.

### UI font

`.font-ui` is the body default and rarely needs to be applied explicitly. Use it to restore the `ui` family on a child element when an ancestor has switched to a different family.

<Example code={`<p class="font-ui">.font-ui</p>`} />

<Callout type="warning">
`.font-text` and `--cx-font-family-text` are deprecated in v0.10.0 and are the same as `.font-ui` and `--cx-font-family-ui`. They are removed in the next breaking release.
</Callout>

### Prose font

Add `.font-prose` to a reading region to switch it to the `prose` family. Combine it with `font-{size}` and `font-{weight}` utilities to take the sizes, line heights and weights of the `prose` scale.

<Example code={`<p class="font-prose">Prose at the size of the surrounding text.</p>
<p class="font-prose font-lg">Large prose text.</p>
<p class="font-prose font-sm font-strong">Small, strong prose text.</p>`} />

Prose sizes and weights use dedicated tokens, separate from the `ui` scale, so a brand can give its reading typeface its own scale. The body, lead, blockquote and cite [text roles](#text-roles) use the `prose` family by default.

### Display font

Add `.font-display` to any element to switch to the display font family. Weight utilities compose with it and take the weights of the display family.

<Example code={`<p class="font-display">Display text.</p>
<p class="font-display font-mass">Display text in the mass weight.</p>`} />

The display family has no size scale, so a size utility on a display element sets the size of the `ui` scale. For display text at a set size, use a [text role](#text-roles) such as `.font-hero` or `.font-h1`, which take their family from the brand.

### Code font

Add `.font-code` to apply the branded monospace font family, suitable for code snippets and technical text. The code font has 3 sizes and 2 weights defined by dedicated design tokens, separate from the `ui` scale. Combine `.font-code` with `font-{size}` and `font-{weight}` utilities to set size and weight.

<Example code={`<p class="font-code font-lg">Large code font.</p>
<p class="font-code">Medium code font.</p>
<p class="font-code font-sm">Small code font.</p>
<p class="font-code font-strong">Strong code font.</p>`} />

Code font sizes and weights use dedicated tokens, separate from the `ui` scale. A code font's `lg` or `strong` may map to a different numeric value than their `.font-ui` equivalents, and line heights often differ to support the readability of code snippets.

<Callout type="info">
When only the font family needs to change and sizes should inherit from surrounding text, use `.font-monospace` instead. It switches `font-family` to the code font without applying any code-specific size, weight, or line-height tokens. Pairing it with weight utilities like `font-strong` may produce unexpected results if the code font does not have that weight registered.
</Callout>

## Text roles

A text role is a named text style of the design tokens, such as a heading level, a lead paragraph or a label. Each role class sets its family, size, line height and weight in one class, and maps to the Figma text style of the same name.

- **Own size and line height**: every role holds its own values, exposed as `--cx-font-size-{role}` and `--cx-line-height-{role}` (`--cx-font-size-lead`, `--cx-line-height-title-lg`). Jumbo and hero keep their sizes in their classes.
- **Family and weight of the role group**: roles of one group share a family and a weight, exposed as `--cx-font-family-{group}` and `--cx-font-weight-{group}`. The groups are `jumbo`, `hero`, `heading`, `lead`, `body`, `title`, `label`, `blockquote` and `cite`. Setting `--cx-font-family-title` changes the family of every title class.
- **Only what the role sets**: a role class sets `font-style`, `text-transform`, `text-decoration` and `letter-spacing` only where the role gives them a value, such as the italic of the blockquote role. Elsewhere the element keeps what it inherits.

<CxTable>
| Role | Classes | Group | Family in the base tokens |
| --- | --- | --- | --- |
| Jumbo | `.font-jumbo` | `jumbo` | `ui` |
| Hero | `.font-hero` | `hero` | `ui` |
| Headings | `.font-h1` – `.font-h6` | `heading` | `ui` |
| Lead | `.font-lead` | `lead` | `prose` |
| Blockquote | `.font-blockquote` | `blockquote` | `prose` |
| Cite | `.font-cite` | `cite` | `prose` |
| Title | `.font-title-lg`, `.font-title`, `.font-title-sm` | `title` | `ui` |
| Body | `.font-body-lg`, `.font-body`, `.font-body-sm` | `body` | `prose` |
| Label | `.font-label-lg`, `.font-label`, `.font-label-sm` | `label` | `ui` |
</CxTable>

A brand moves a group to another family in its tokens: the default Chassis brand sets the jumbo, hero, heading and title groups in its display typeface.

```css
:root {
  --cx-font-family-title: var(--cx-font-family-prose);
}
```

### Jumbo

`.font-jumbo` targets large-scale headlines where maximum visual impact is needed.

<Example code={`<p class="font-jumbo">This is jumbo text, which can be used for headlines.</p>`} />

### Hero

`.font-hero` targets hero sections and prominent introductory text.

<Example code={`<p class="font-hero">This is a hero text, which can be used in hero slides.</p>`} />

### Heading levels

`.font-h1` through `.font-h6` are the heading roles; see [Heading classes](#heading-classes).

### Lead

`.font-lead` increases the visual weight of an introductory paragraph to draw the reader's eye.

<Example code={`<p class="font-lead">
    This is a lead paragraph. It stands out from regular paragraphs.
  </p>`} />

### Blockquote and cite

`.font-blockquote` and `.font-cite` apply the quote and attribution roles without the margins and the em dash of `.blockquote` and `.attribution`.

<Example code={`<p class="font-blockquote">A well-known quote, set in the blockquote role.</p>
<p class="font-cite">Someone famous, set in the cite role.</p>`} />

### Title

Title styles come in three sizes for use in card headers, section labels, and similar UI elements.

<Example code={`<p class="font-title-lg">A special title in large size.</p>
<p class="font-title">A special title in medium size.</p>
<p class="font-title-sm">A special title in small size.</p>`} />

### Body

Body styles in three sizes provide typographic control for article and long-form content.

<Example code={`<p class="font-body-lg">A large text class suitable for various contexts, such as articles, blogs, and more. It features custom styling to enhance readability and design.</p>
<p class="font-body">A medium text class suitable for various contexts, such as articles, blogs, and more. It features custom styling to enhance readability and design.</p>
<p class="font-body-sm">A small text class suitable for various contexts, such as articles, blogs, and more. It features custom styling to enhance readability and design.</p>`} />

### Label

Label styles in three sizes suit metadata, tags, and supporting information where compact text is needed.

<Example code={`<p class="font-label-lg">A large label class for metadata, tags, and supporting information.</p>
<p class="font-label">A medium label class for metadata, tags, and supporting information.</p>
<p class="font-label-sm">A small label class for metadata, tags, and supporting information.</p>`} />
