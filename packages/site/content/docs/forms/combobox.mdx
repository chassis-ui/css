## Introduction

A combobox is a select-style picker with one of two trigger styles:

- **Input trigger** — `<input class="combobox-value">` inside the toggle. Typing filters the list inline. The same input also displays the selected value when the menu is closed.
- **Button trigger** — `<span class="combobox-value">` (or any non-input element) inside the toggle. The toggle is display-only, like a native `<select>`. Add a `.combobox-search-input` inside the menu when the list is long enough that filtering helps.

The toggle, the items and their decoration are written in HTML. The plugin opens and closes the menu, filters the items, tracks the selection, handles the keyboard, and creates a hidden `<input>` for form submission.

## Basic structure

A combobox needs three things: a toggle marked with `data-cx-toggle="combobox"`, a `.combobox-value` element inside it, and a sibling `.menu` whose buttons carry `data-cx-value` attributes.

The examples on this page show the markup of the combobox itself and leave out the visible label. [In a form field](#in-a-form-field) shows the labelled pattern to use in production.

### Input trigger

The toggle is a wrapper `<div class="form-input combobox">` with a text input inside. Typing in it filters the menu items.

<Example code={`<div class="form-input combobox"
       data-cx-toggle="combobox"
       data-cx-name="option">
    <input type="text" class="combobox-value" placeholder="Select an item…" autocomplete="off">
  </div>
  <div class="menu" role="listbox">
    <button class="menu-item" type="button" role="option" data-cx-value="1">Option one</button>
    <button class="menu-item" type="button" role="option" data-cx-value="2">Option two</button>
    <button class="menu-item" type="button" role="option" data-cx-value="3">Option three</button>
  </div>`} />

### Button trigger

The toggle is itself a `<button class="form-input combobox">`. The user cannot type into the toggle, so the menu opens like a native `<select>`. Give it `role="combobox"`, `aria-expanded="false"` and an `aria-controls` that points at the menu: the accessible name then comes from the label alone, and the text of the toggle is read as its value. Use `data-cx-placeholder` to set the text shown when nothing is selected — the plugin writes it to the `.combobox-value` element whenever the selection is empty.

<Example code={`<button class="form-input combobox"
          type="button"
          role="combobox"
          aria-label="Select an item"
          aria-controls="comboButtonMenu"
          aria-expanded="false"
          data-cx-toggle="combobox"
          data-cx-name="option"
          data-cx-placeholder="Select an item…">
    <span class="combobox-value"></span>
  </button>
  <div class="menu" id="comboButtonMenu" role="listbox">
    <button class="menu-item" type="button" role="option" data-cx-value="1">Option one</button>
    <button class="menu-item" type="button" role="option" data-cx-value="2">Option two</button>
    <button class="menu-item" type="button" role="option" data-cx-value="3">Option three</button>
  </div>`} />

### Pre-selected value

Mark the initially selected menu item with both the `.selected` class and `aria-selected="true"`. On initialization the plugin reads `.selected` to set the displayed value of the toggle and the hidden input, and from then on it keeps `aria-selected` in sync with the selection.

<Example code={`<div class="form-input combobox"
       data-cx-toggle="combobox"
       data-cx-name="role">
    <input type="text" class="combobox-value" placeholder="Choose a role…" autocomplete="off">
  </div>
  <div class="menu" role="listbox">
    <button class="menu-item" type="button" role="option" data-cx-value="admin">Admin</button>
    <button class="menu-item selected" type="button" role="option" aria-selected="true" data-cx-value="editor">Editor</button>
    <button class="menu-item" type="button" role="option" data-cx-value="viewer">Viewer</button>
  </div>`} />

## Disabled

A combobox can be disabled as a whole, and individual menu items can be disabled too.

### Whole combobox

Disable the toggle in one of three equivalent ways — the plugin keeps all three sources in sync:

- `disabled` attribute on the toggle (button trigger only)
- `disabled` attribute on the embedded `<input class="combobox-value">` (input trigger)
- `.disabled` class on the toggle (either trigger)

The hidden input is also disabled, so the value is excluded from form submission.

<Example class="vstack gap-md" code={`<div class="form-input combobox" data-cx-toggle="combobox">
    <input type="text" class="combobox-value" placeholder="Unavailable…" autocomplete="off" disabled>
  </div>
  <div class="menu" role="listbox">
    <button class="menu-item" type="button" role="option" data-cx-value="1">Option one</button>
    <button class="menu-item" type="button" role="option" data-cx-value="2">Option two</button>
  </div>

  <button class="form-input combobox"
          type="button"
          role="combobox"
          aria-label="Select an item"
          aria-controls="comboDisabledMenu"
          aria-expanded="false"
          data-cx-toggle="combobox"
          data-cx-placeholder="Unavailable…"
          disabled>
    <span class="combobox-value"></span>
  </button>
  <div class="menu" id="comboDisabledMenu" role="listbox">
    <button class="menu-item" type="button" role="option" data-cx-value="1">Option one</button>
    <button class="menu-item" type="button" role="option" data-cx-value="2">Option two</button>
  </div>`} />

### Individual items

Add `disabled` (or `.disabled`) to any `.menu-item` to make that option unselectable. The combobox itself stays usable.

<Example code={`<div class="form-input combobox" data-cx-toggle="combobox">
    <input type="text" class="combobox-value" placeholder="Select an option…" autocomplete="off">
  </div>
  <div class="menu" role="listbox">
    <button class="menu-item" type="button" role="option" data-cx-value="1">Available option</button>
    <button class="menu-item" type="button" role="option" data-cx-value="2" disabled>Unavailable option</button>
    <button class="menu-item" type="button" role="option" data-cx-value="3">Another option</button>
  </div>`} />

To disable or re-enable a combobox at runtime, call the `disable()` and `enable()` methods.

## Filtering long lists

Filtering hides items whose visible text does not match the current query. The mechanism differs between trigger styles: input-trigger comboboxes filter inline as the user types, while button-trigger comboboxes use a dedicated search field inside the menu.

### Inline filtering

An input-trigger combobox filters without extra markup: typing into the `.combobox-value` input hides the items whose visible text does not match. When nothing matches, the menu closes and the typed text stays; the menu opens again as soon as the text matches an item.

### Search field

For button-trigger comboboxes, add a `.combobox-search-input` inside the menu. When the menu opens, the focus moves to the search field. Wrap it in `.combobox-search` to keep it at the top of the scrolling menu, and add a `.combobox-no-results` element for the empty state — the plugin removes its `.d-none` class when no item matches.

<Example code={`<button class="form-input combobox"
          type="button"
          role="combobox"
          aria-label="Select a country"
          aria-controls="comboSearchMenu"
          aria-expanded="false"
          data-cx-toggle="combobox"
          data-cx-name="country"
          data-cx-placeholder="Select a country…">
    <span class="combobox-value"></span>
  </button>
  <div class="menu" id="comboSearchMenu" role="listbox">
    <div class="combobox-search">
      <input type="text" class="form-input combobox-search-input sm" placeholder="Search…" autocomplete="off" aria-label="Filter countries">
    </div>
    <button class="menu-item" type="button" role="option" data-cx-value="us">United States</button>
    <button class="menu-item" type="button" role="option" data-cx-value="uk">United Kingdom</button>
    <button class="menu-item" type="button" role="option" data-cx-value="ca">Canada</button>
    <button class="menu-item" type="button" role="option" data-cx-value="au">Australia</button>
    <button class="menu-item" type="button" role="option" data-cx-value="de">Germany</button>
    <button class="menu-item" type="button" role="option" data-cx-value="fr">France</button>
    <button class="menu-item" type="button" role="option" data-cx-value="jp">Japan</button>

### Ignoring diacritics

Enable `searchNormalize` (with `data-cx-search-normalize="true"` or the option) to strip diacritics before comparing, so typing "uber" matches "über". The option applies to inline filtering and to the search field.

## In a form field

Wrap the label, the combobox and any feedback in a [form field]([[docsref:/forms/form-field]]). This is the pattern to use in production: a visible `<label for="…">` gives the combobox its accessible name and focuses it on click, and the `aria-label` of the menu repeats that name so the toggle and the listbox are announced alike.

<Example code={`<div class="form-field">

    <div class="form-help">The billing region.</div>
  </div>`} />

## Form submission

When `data-cx-name` is present on the toggle, the plugin inserts a hidden `<input>` immediately before the toggle and keeps its `value` in sync with the selection. Without `data-cx-name`, no hidden input is created and the combobox's value is not submitted.

```html
<!-- Authored markup -->
<div class="form-input combobox"
     data-cx-toggle="combobox"
     data-cx-name="country">
  ...
</div>
<div class="menu">...</div>

<!-- What the plugin inserts before the toggle on init -->
<input type="hidden" name="country" value="us">
```

For multi-select, the hidden input's value is a comma-separated list — `"html,css,js"`. When the combobox is disabled, the hidden input also gets `disabled`, so the value is excluded from form submission.

## Accessibility

The accessibility of a combobox has two parts: the state the plugin keeps in sync, and the roles and names the markup has to carry.

### Managed state

The plugin keeps this state in sync without extra markup:

- `aria-expanded` on the toggle is `true` while the menu is open and `false` while it is closed.
- `aria-selected` on each `.menu-item` is `"true"` on selected items and `"false"` on the others, from initialization on.
- The `.disabled` class and the `aria-disabled` attribute of the toggle and the `disabled` attribute of the trigger (the button, or the embedded input) follow each other. The hidden input is disabled with them, so a disabled combobox does not submit a value.

### Required markup

The plugin does not add the roles and names that identify the combobox and its options to assistive technologies. Write them in the markup:

- **Accessible name for the combobox.** Either a visible `<label for="…">` pointing to the input/button id, or `aria-label`/`aria-labelledby` on the toggle. The [In a form field](#in-a-form-field) section shows the canonical labelled pattern.
- **`role="combobox"`, `aria-controls` and `aria-expanded="false"`** on a button trigger, with `aria-controls` naming the `id` of the `.menu`. The role requires `aria-expanded` before the menu first opens; the plugin keeps it in sync after that. Without the role, a `<button>` is named by its text, and a label that does not hold the placeholder or the selected value breaks [WCAG 2.5.3 Label in Name](https://www.w3.org/WAI/WCAG22/Understanding/label-in-name.html).
- **`role="listbox"`** on the `.menu`. When labelled, also add `aria-label` (or `aria-labelledby`) matching the toggle's accessible name. For multi-select, add `aria-multiselectable="true"`.
- **`role="option"`** on each `.menu-item`, and `aria-selected="true"` on any pre-selected items.
- **`role="none"`** on `.menu-header` so screen readers skip the headers.
- **`aria-hidden="true"`** on decorative SVG icons inside items.

### Keyboard interaction

Every action of a combobox has a key. What a key does depends on where the focus is:

- **Toggle focused:** <kbd>↓</kbd> / <kbd>↑</kbd> opens the menu when it is closed and focuses the first or last visible item. <kbd>Enter</kbd> or <kbd>Space</kbd> opens the menu of a button trigger; in the input of an input trigger both keys keep their native behavior. <kbd>Esc</kbd> closes an open menu and leaves the focus where it is.
- **Item focused:** <kbd>↓</kbd> / <kbd>↑</kbd> moves between the visible items and wraps at the ends. <kbd>Home</kbd> / <kbd>End</kbd> moves to the first or last item. <kbd>Enter</kbd> or <kbd>Space</kbd> selects the focused item. <kbd>Esc</kbd> closes the menu and returns the focus to the toggle. <kbd>Tab</kbd> closes the menu and moves the focus to the control after the combobox.
- **Search field focused:** <kbd>↓</kbd> moves to the first visible item. <kbd>Esc</kbd> closes the menu and returns the focus to the toggle.

## JavaScript API

The Combobox plugin opens and closes the menu, filters and selects items, and keeps the hidden input and the ARIA state in sync. Chassis JS ships as an ES module — import the `Combobox` class:

```js
import { Combobox } from '@chassis-ui/css'
```

### Triggers

A toggle with `data-cx-toggle="combobox"` is initialized when the page loads, or on its first click when it is added later. The plugin reads these attributes on initialization:

<CxTable>
| Attribute | On | Description |
| --- | --- | --- |
| `data-cx-toggle="combobox"` | toggle | Initializes the combobox. |
| `data-cx-name` | toggle | `name` of the hidden input the plugin creates. Omit it to create no hidden input. |
| `data-cx-placeholder` | toggle | Text shown in the toggle when nothing is selected (button trigger). |
| `data-cx-multiple` | toggle | `"true"` enables multi-select. |
| `data-cx-search-normalize` | toggle | `"true"` strips diacritics before comparing during filtering. |
| `data-cx-value` | `.menu-item` | The value submitted. Items without this attribute are decorative and not selectable. |
</CxTable>

### Initialization

For runtime control (opening and closing, disabling, disposing), or for options computed at runtime, create the instance with the `Combobox` class on the toggle:

```js
const toggle = document.querySelector('[data-cx-toggle="combobox"]')
const combobox = new Combobox(toggle, {
  name: 'country',
  searchNormalize: true
})
```

### Methods

The plugin exposes instance methods to open, close, disable and dispose a combobox, and the static lookup methods shared by every Chassis plugin:

<CxTable>
| Method | Description |
| --- | --- |
| `show` | Opens the menu. |
| `hide` | Closes the menu. |
| `toggle` | Opens or closes based on current state. |
| `disable` | Disables the combobox and closes the menu if open. |
| `enable` | Re-enables a disabled combobox. |
| `dispose` | Destroys the instance and removes the hidden input. |
| `getInstance` | Static. Returns the combobox instance attached to a toggle, or `null`. |
| `getOrCreateInstance` | Static. Returns the instance or creates one. |
</CxTable>

### Options

<JsDataAttributes />

<CxTable>
| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `multiple` | boolean | `false` | Enable multi-select. Selections toggle and the menu stays open. |
| `name` | string \| null | `null` | Name of the hidden input the plugin creates. |
| `placeholder` | string | `''` | Placeholder for the toggle (button trigger). |

| `placement` | string | `'bottom-start'` | Floating UI placement for the menu. |

### Events

All events fire on the toggle element. `show.cx.combobox` and `hide.cx.combobox` are cancelable.

<CxTable>
| Event | Description |
| --- | --- |
| `show.cx.combobox` | Fires when `show()` is called, before the menu opens. Call `event.preventDefault()` to keep it closed. |
| `shown.cx.combobox` | Fires after the menu is visible. |
| `hide.cx.combobox` | Fires when `hide()` is called, before the menu closes. Call `event.preventDefault()` to keep it open. |
| `hidden.cx.combobox` | Fires after the menu is hidden. |
| `change.cx.combobox` | Fires after a selection. `event.value` is a string for single select and an array of strings for multi-select; `event.item` is the `.menu-item` whose selection changed. |
</CxTable>
