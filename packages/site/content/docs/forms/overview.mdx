## Overview

The form components build on the [form styles of Reboot]([[docsref:/content/reboot#form-elements]]) with classes that give inputs, selects, checks, and ranges the same look in every browser. The pages of this section cover one component each; this page covers what they share.

Every form component reads its colors, sizes, and spacing from custom properties, so you can theme all of them at once or override a single control.

Use the `type` attribute that matches the data (`email`, `number`, `tel`, and so on): the browser then validates the value and shows the fitting keyboard and controls.

A form with a labeled input, a help text, a checkbox, and a submit button looks like this:

<Example code={`<form>
    <div class="mb-md">
      <label for="exampleInputEmail1" class="form-label">Email address</label>
      <input type="email" class="form-input" id="exampleInputEmail1" aria-describedby="emailHelp">
      <div id="emailHelp" class="form-help">We'll never share your email with anyone else.</div>
    </div>
    <div class="mb-md">
      <label for="exampleInputPassword1" class="form-label">Password</label>
      <input type="password" autocomplete="current-password" class="form-input" id="exampleInputPassword1">
    </div>
    <div class="mb-md form-check">
      <input type="checkbox" class="check-input" id="exampleCheck1">
      <label for="exampleCheck1">Check me out</label>
    </div>
    <button type="submit" class="button primary">Submit</button>
  </form>`} />

## Disabled forms

Add the `disabled` attribute to an input to make it unavailable. The input takes the disabled form colors, and the browser stops interaction with it.

```html
<input class="form-input" id="disabledInput" type="text" placeholder="Disabled input here..." disabled>
```

To disable several controls at once, add `disabled` to a parent `<fieldset>`. The browser disables every native form element inside it (`<input>`, `<select>`, `<textarea>`, and `<button>`), and they take their disabled styles.

A link styled as a button, such as `<a class="button">`, is not a form element, so a disabled fieldset does not disable it. Chassis gives it the disabled button styles and `pointer-events: none`, which stops mouse interaction only. Add `tabindex="-1"` to keep it out of the tab order and `aria-disabled="true"` to tell assistive technologies that it is disabled.

<Example code={`<form>
    <fieldset disabled>
      <legend>Disabled fieldset example</legend>
      <div class="mb-md">
        <label for="disabledTextInput" class="form-label">Disabled input</label>
        <input type="text" id="disabledTextInput" class="form-input" placeholder="Disabled input">
      </div>
      <div class="mb-md">
        <label for="disabledSelect" class="form-label">Disabled select menu</label>
        <select id="disabledSelect" class="form-input">
          <option>Disabled select</option>
        </select>
      </div>
      <div class="mb-md">
        <div class="form-check">
          <input class="check-input" type="checkbox" id="disabledFieldsetCheck">
          <label for="disabledFieldsetCheck">
            Can't check this
          </label>
        </div>
      </div>
      <button type="submit" class="button primary">Submit</button>
    </fieldset>
  </form>`} />

## Dark mode

Form components take their colors from custom properties that follow the color mode. Add `data-cx-theme="dark"` to a container, or to a single form element, to render it with the dark palette.

### Inheritance and override

Form elements inherit the theme of their parent, and a `data-cx-theme` attribute on a single control overrides it:

- `data-cx-theme="dark"` on a container puts every form control inside it in dark mode
- `data-cx-theme="light"` on a control inside a dark container sets that control apart

The example has a light and a dark form, each with controls of the opposite theme:

<Example code={`<div class="grid grid-cols-1 md:grid-cols-2 gap-xl">
    <form class="context p-md" data-cx-theme="light">
      <div class="mb-md">
        <label for="exampleSelectDark" class="form-label">Example Select</label>
        <select class="form-input" id="exampleSelectDark" data-cx-theme="dark">
          <option selected>Choose an option</option>
          <option>Option 1</option>
          <option>Option 2</option>
        </select>
      </div>
      <div class="mb-md">
        <label for="exampleInputDark" class="form-label">Example Input</label>
        <input type="text" class="form-input" id="exampleInputDark" data-cx-theme="dark" placeholder="Dark themed input">
      </div>
      <div class="mb-md form-check">
        <input type="checkbox" class="check-input" id="exampleCheckDark" data-cx-theme="dark">
        <label for="exampleCheckDark">Example checkbox</label>
      </div>
      <button type="submit" class="button primary">Submit</button>
    </form>

    <form class="context p-md" data-cx-theme="dark">
      <div class="mb-md">
        <label for="exampleSelectLight" class="form-label">Example Select</label>
        <select class="form-input" id="exampleSelectLight" data-cx-theme="light">
          <option selected>Choose an option</option>
          <option>Option 1</option>
          <option>Option 2</option>
        </select>
      </div>
      <div class="mb-md">
        <label for="exampleInputLight" class="form-label">Example Input</label>
        <input type="text" class="form-input" id="exampleInputLight" data-cx-theme="light" placeholder="Light themed input">
      </div>
      <div class="mb-md form-check">
        <input type="checkbox" class="check-input" id="exampleCheckLight" data-cx-theme="light">
        <label for="exampleCheckLight">Example checkbox</label>
      </div>
      <button type="submit" class="button primary">Submit</button>
    </form>
  </div>`} />

<Callout type="info">
  Where a whole form shares a theme, set `data-cx-theme` once on its container instead of on each control: the markup stays shorter, and a change of theme is made in one place.
</Callout>

## Accessibility

The form components style native controls, so roles, states, and keyboard interaction come from the browser. Names, groups, and error messages depend on your markup:

### Accessible names

Every form control needs an accessible name that says what it is for. Without one, users of screen readers cannot tell which information a field asks for.

**Use explicit labels:**

- Connect inputs with labels using the `for` attribute that matches the input's `id`
- Place checkboxes and radios inside label elements for automatic association

**When a visible label is not possible:**

- Hide a label visually with the `.visually-hidden` class
- Reference existing content with `aria-labelledby`
- Use `aria-label` for a short, explicit name
- Add a `title` attribute only as a last resort

Never rely on the `placeholder` attribute alone for the name of a control. Placeholders:

- Disappear when the field contains content
- Often have low color contrast
- Cannot be accessed by all assistive technologies consistently

### State communication

A form control has to convey its state (required, invalid, disabled) in the markup as well as visually:

- Use the `required` attribute for mandatory fields
- Set `aria-invalid="true"` on a field with a validation error
- Associate each error message with its field through `aria-describedby`

The page of each form component has an accessibility section with the details for that component.

## CSS

<DocsCSS name="Form" plural />

Form elements share one set of custom properties, named by state: `--form-idle-*`, `--form-focus-*`, `--form-disabled-*`. A component assigns the property of the current state to a local property such as `--bg-color` and uses that in its declarations. The idle value reads an override property first, so you can restyle one control without touching the shared set:

```css
.form-input {
  --bg-color: var(--input-bg-color, var(--form-idle-bg-regular));
  background-color: var(--bg-color);
}
.form-input:disabled {
  --bg-color: var(--form-disabled-bg-regular);
}
```
