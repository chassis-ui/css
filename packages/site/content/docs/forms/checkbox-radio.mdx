## Introduction

The `.check-input` class replaces the browser's default checkbox and radio rendering with the form colors and icons of Chassis, and the `.form-check` container sets the gap, the font size, and the alignment of the control and its label. The inputs stay native `<input type="checkbox">` and `<input type="radio">` elements, so keyboard interaction, form submission, and the accessibility semantics are the browser's own.

Two markup patterns give the same result: **sibling** markup, an `<input>` and a `<label>` connected with `id` and `for` inside a `.form-check` element, and **nested** markup, where the `<label>` itself carries `.form-check` and wraps the `<input>`.

## Basic structure

Add `.check-input` to an `<input type="checkbox">` or `<input type="radio">` element and wrap it, with its label, in a `.form-check` container. The container reserves the space of the input at its inline start and aligns the label text next to it.

### Checkboxes

A checkbox is an `<input type="checkbox">` with `.check-input`. The example shows the sibling and the nested markup pattern.

<Example class="vstack gap-xs" code={`<!-- Sibling markup pattern -->
  <div class="form-check">
    <input class="check-input" type="checkbox" id="checkSibling">
    <label for="checkSibling">Sibling checkbox</label>
  </div>

  <!-- Nested markup pattern -->
  <label class="form-check">
    <input class="check-input" type="checkbox" id="checkNested" checked>
     Nested checkbox
</label>`} />

### Radio buttons

A radio button is an `<input type="radio">` with `.check-input`. Radio buttons that share a `name` form a group in which only one option is selected at a time.

<Example class="vstack gap-xs" code={`<label class="form-check">
    <input class="check-input" type="radio" name="radioExample">
    Option one
  </label>
  <label class="form-check">
    <input class="check-input" type="radio" name="radioExample" checked>
    Option two
</label>`} />

### Indeterminate state

The indeterminate state is a third visual state of a checkbox, typically for a parent option whose children are partly selected. HTML has no attribute for it: set the `indeterminate` property of the input with JavaScript.

<Example addStackblitzJs class="cxd-example-indeterminate vstack gap-xs" code={`<label class="form-check">
    <input class="check-input" type="checkbox" value="" id="checkIndeterminate">
    Indeterminate checkbox
  </label>`} />

### Disabled state

Add the `disabled` attribute to an input to make it unavailable. The input takes the disabled form colors, and a `.form-check` container that holds a disabled input mutes its label text.

<Example addStackblitzJs class="cxd-example-indeterminate vstack gap-xs" code={`<label class="form-check">
    <input class="check-input" type="checkbox" value="" id="checkDisabled" disabled>
    Disabled checkbox
  </label>
  <label class="form-check">
    <input class="check-input" type="checkbox" value="" id="checkCheckedDisabled" checked disabled>
    Disabled checked checkbox
  </label><label class="form-check">
    <input class="check-input" type="checkbox" value="" id="checkIndeterminateDisabled" disabled>
    Disabled indeterminate checkbox
  </label>
  <label class="form-check">
    <input class="check-input" type="radio" value="" id="radioDisabled" disabled>
    Disabled radio
  </label>
  <label class="form-check">
    <input class="check-input" type="radio" value="" id="radioCheckedDisabled" checked disabled>
    Disabled checked radio
  </label>`} />

### Switches

A switch is a checkbox with `role="switch"`: the attribute selects the switch styling, a track with a toggle that moves to the inline end when the input is checked. No extra class is needed.

The role also tells assistive technologies that the control turns something on or off; technologies that do not support it announce a regular checkbox. Switches support the `disabled` attribute.

<Example class="vstack gap-xs" code={`<label class="form-check">
    <input class="check-input" type="checkbox" role="switch" id="switchCheckDefault">
    Default switch checkbox input
  </label>
  <label class="form-check">
    <input class="check-input" type="checkbox" role="switch" id="switchCheckChecked" checked>
    Checked switch checkbox input
  </label>
  <label class="form-check">
    <input class="check-input" type="checkbox" role="switch" id="switchCheckDisabled" disabled>
    Disabled switch checkbox input
  </label>
  <label class="form-check">
    <input class="check-input" type="checkbox" role="switch" id="switchCheckCheckedDisabled" checked disabled>
    Disabled checked switch checkbox input
  </label>`} />

## Descriptive labels

Place a `.form-help` element inside the `.form-check` container to describe an option below its label. Add `.d-inline` to keep the description on the line of the label.

<Example class="vstack gap-xs" code={`<label class="form-check">
    <input class="check-input" type="checkbox">
    Checkbox with description
    <small class="form-help">
      This is a helpful description for the checkbox.
    </small>
  </label>
  <label class="form-check">
    <input class="check-input" type="checkbox">
    Checkbox with inline description
    <small class="form-help fg-subtle d-inline">
      – This is an inline help text for the checkbox.
    </small>
  </label>`} />

### Without visible labels

Omit the `.form-check` container for a control without a visible label, such as a checkbox in a table row. The input still needs an accessible name: add `aria-label` or `aria-labelledby` (see [forms accessibility]([[docsref:/forms/overview/#accessibility]])).

<Example class="hstack gap-xs" code={`<input class="check-input" type="checkbox" id="checkboxNoLabel" value="" aria-label="Subscribe to newsletter">
  <input class="check-input" type="radio" name="radioNoLabel" id="radioNoLabel1" value="1" aria-label="Select first option">
  <input class="check-input" type="radio" name="radioNoLabel" id="radioNoLabel2" value="2" aria-label="Select second option">`} />

## Sizing options

Add `.sm` or `.lg` to the `.form-check` container to change the size of the input, the gap, and the font size of the label together.

<Example class="vstack gap-xs" code={`<div class="form-check lg">
    <input class="check-input" type="checkbox" id="checkLarge">
    <label for="checkLarge">
      Large checkbox
    </label>
  </div>
  <div class="form-check">
    <input class="check-input" type="checkbox" id="checkMedium">
    <label for="checkMedium">
      Default checkbox
    </label>
  </div>
  <div class="form-check sm">
    <input class="check-input" type="checkbox" id="checkSmall">
    <label for="checkSmall">
      Small checkbox
    </label>
  </div>`} />

The size classes apply to switches in the same way: `.sm` or `.lg` on the `.form-check` container sets the width and height of the track and the toggle with the label.

<Example class="vstack gap-xs" code={`<label class="form-check lg">
    <input class="check-input" type="radio" name="radioSize" id="switchLarge">
      Large switch
  </label>
  <label class="form-check">
    <input class="check-input" type="radio" name="radioSize" id="switchMedium" checked>
    Default switch
  </label>
  <label class="form-check sm">
    <input class="check-input" type="radio" name="radioSize" id="switchSmall">
    Small switch
  </label>`} />

### Sizing without labels

For a control without a `.form-check` container, add `.sm` or `.lg` to the `.check-input` element itself.

<Example code={`<input class="check-input lg" type="checkbox">
  <input class="check-input" type="checkbox">
  <input class="check-input sm" type="checkbox">
    <span class="vr mx-md"></span>
  <input class="check-input lg" name="radioSizeInput" type="radio">
  <input class="check-input" name="radioSizeInput" type="radio">
  <input class="check-input sm" name="radioSizeInput" type="radio">
    <span class="vr mx-md"></span>
  <input class="check-input lg" role="switch" name="switchSizeInputLarge" type="checkbox">
  <input class="check-input" role="switch" name="switchSizeInputMedium" type="checkbox">
  <input class="check-input sm" role="switch" name="switchSizeInputSmall" type="checkbox">`} />

## Layout options

`.form-check` elements are block-level and stack vertically. Flex utilities place them on one line, and the `.reverse` modifier moves the input to the other side of the label.

### Inline layout

Wrap the checks in a flex container, with [flex utilities]([[docsref:/utilities/flex]]) and a [gap utility]([[docsref:/utilities/gap]]), to display them on one line.

<Example code={`<div class="d-flex gap-md">
    <label class="form-check">
      <input class="check-input" type="radio" name="inlineRadioOptions" id="inlineRadio1" value="option1">
      Option one
    </label>
    <label class="form-check">
      <input class="check-input" type="radio" name="inlineRadioOptions" id="inlineRadio2" value="option2">
      Option two
    </label>
    <label class="form-check">
      <input class="check-input" type="radio" name="inlineRadioOptions" id="inlineRadio3" value="option3" disabled>
      Option three (disabled)
    </label>
  </div>`} />

### Reversed layout

Add `.reverse` to the `.form-check` container to place the input at the inline end of the label and align the text to the end.

<Example code={`<div class="form-check reverse">
    <input class="check-input" type="checkbox" value="" id="reverseCheck1">
    <label for="reverseCheck1">
      Reverse checkbox
    </label>
  </div>
  <div class="form-check reverse">
    <input class="check-input" type="checkbox" value="" id="reverseCheck2" disabled>
    <label for="reverseCheck2">
      Disabled reverse checkbox
    </label>
  </div>

  <div class="form-check reverse">
    <input class="check-input" type="checkbox" role="switch" id="switchCheckReverse">
    <label for="switchCheckReverse">Reverse switch checkbox input</label>
  </div>`} />

## Button checks

Button checks are checkboxes and radio buttons that look like buttons. Add `.button` and `.button-check` to a `<label>` and nest the input in it: `.button-check` hides the input visually and keeps it focusable, and the label shows the checked, focused, and disabled states of the input.

### Checkbox toggles

A `.button-check` label with an `<input type="checkbox">` toggles on and off independently of the buttons next to it.

<Example code={`<label class="button button-check default">
    <input type="checkbox" autocomplete="off">
    Button check
  </label>
  <label class="button button-check default">
    <input type="checkbox" checked autocomplete="off">
    Checked
  </label>
  <label class="button button-check default">
    <input type="checkbox" autocomplete="off" disabled>
    Disabled
  </label>`} />

<Callout type="info">
Screen readers announce a button check as "checkbox, checked" or "checkbox, not checked", since the input keeps its role. A toggle of the [button component]([[docsref:/components/button#toggle-functionality]]) is announced as "button" or "button, pressed". Use a button check when the control sets a state, and a toggle button when it triggers an action.
</Callout>

### Radio toggles

A `.button-check` label with an `<input type="radio">` is one option of a group: inputs that share a `name` allow one selection at a time.

<Example code={`<label class="button button-check default">
    <input type="radio" name="options" autocomplete="off" checked>
    Checked
  </label>
  <label class="button button-check default">
    <input type="radio" name="options" autocomplete="off">
    Radio
  </label>
  <label class="button button-check default">
    <input type="radio" name="options" autocomplete="off" disabled>
    Disabled
  </label>
  <label class="button button-check default">
    <input type="radio" name="options" autocomplete="off">
    Radio
  </label>`} />

### Style variants

Button checks take the context and style classes of the [button component]([[docsref:/components/button]]), such as `.primary`, `.smooth`, and `.outline`.

<Example class="button-examples" code={`<label class="button button-check default">
    <input type="radio" name="styleOptions" autocomplete="off">
    Default
  </label>
  <label class="button button-check primary">
    <input type="radio" name="styleOptions" checked autocomplete="off">
    Primary
  </label>
  <label class="button button-check primary smooth">
    <input type="radio" name="styleOptions" autocomplete="off" checked>
    Primary smooth
  </label>
  <label class="button button-check secondary outline">
    <input type="radio" name="styleOptions" autocomplete="off">
    Secondary outlined
  </label>`} />

## Modern inputs

A second markup pattern puts `.check-input` on a wrapper around the input instead of on the input itself. The wrapper is a context element, so a context class on it colors the checked state, and the check, radio, and indeterminate icons are drawn by the wrapper instead of a background image of the input.

Both patterns are part of the build and work side by side: `.check-input` on an `<input>` selects the first one, `.check-input` on any other element selects this one.

### Usage patterns

Wrap the `<input>` in a `.check-input` element, a `<span>` in the examples, and add a context class to the wrapper. The wrapper works inside a `.form-check` container with nested and with sibling markup.

<Example class="vstack gap-xs" code={`<!-- Nested input pattern -->
  <label class="form-check">
    <span class="check-input secondary">
      <input type="checkbox" id="checkNestedModern" checked>
    </span>
    Nested input with secondary context color
  </label>

  <!-- Sibling input pattern -->
  <div class="form-check">
    <span class="check-input secondary">
      <input type="checkbox" id="checkSiblingModern" checked>
    </span>
    <label for="checkSiblingModern">Sibling input with secondary context color</label>
  </div>`} />

### Context variants

Every context class is available on the wrapper. The checked input takes the active background and foreground colors of that context.

<Example class="vstack gap-xs" code={getData('context-colors').map((contextColor) => `<label class="form-check">
    <span class="check-input ${contextColor.name}"><input type="checkbox" checked></span>
    ${contextColor.title} checkbox
  </label>`)} />

### Disabled inputs

Add the `disabled` attribute to the `<input>` inside the wrapper. The wrapper switches to the disabled colors of its context, and a sibling `<label>` is muted with it.

<Example class="hstack gap-xs" code={getData('context-colors').map((contextColor) => `<span class="check-input ${contextColor.name}">
    <input type="checkbox" checked disabled>
  </span>`)} />

### Radio inputs

The wrapper draws a radio indicator when it holds an `<input type="radio">`.

<Example class="hstack gap-xs" code={getData('context-colors').map((contextColor) => `<span class="check-input ${contextColor.name}">
      <input type="radio" name="radioContext">
    </span>`)} />

### Indeterminate checks

The wrapper shows the indeterminate icon when the `indeterminate` property of its checkbox is set.

<Example class="hstack gap-xs cxd-example-indeterminate" code={getData('context-colors').map((contextColor) => `<span class="check-input ${contextColor.name}">
    <input type="checkbox" id="check${contextColor.name}Indeterminate">
  </span>`)} />

### Switch role

A wrapper around an input with `role="switch"` renders as a switch, and its context class colors the checked track.

<Example class="vstack gap-xs" code={getData('context-colors').map((contextColor) => `<label class="form-check">
    <span class="check-input ${contextColor.name}">
      <input type="checkbox" role="switch" checked>
    </span>
    ${contextColor.title} switch
  </label>`)} />

### Wrapper sizes

Add `.sm` or `.lg` to the `.form-check` container, or to the `.check-input` wrapper when it stands alone, to change the size of the control.

<Example class="vstack gap-xs" code={`<label class="form-check lg">
    <span class="check-input secondary">
      <input type="checkbox" checked>
    </span>
    Large checkbox
  </label>
  <label class="form-check">
    <span class="check-input secondary">
      <input type="checkbox" checked>
    </span>
    Default checkbox
  </label>
  <label class="form-check sm">
    <span class="check-input secondary">
      <input type="checkbox" checked>
    </span>
    Small checkbox
  </label>
  <label class="form-check lg">
    <span class="check-input secondary">
      <input type="checkbox" role="switch" checked>
    </span>
    Large switch
  </label>
  <label class="form-check">
    <span class="check-input secondary">
      <input type="checkbox" role="switch" checked>
    </span>
    Default switch
  </label>
  <label class="form-check sm">
    <span class="check-input secondary">
      <input type="checkbox" role="switch" checked>
    </span>
    Small switch
  </label>`} />

<Example class="hstack gap-xs" code={`<span class="check-input secondary sm">
    <input type="checkbox" name="checkContextSizeSmall">
  </span>
  <span class="check-input secondary">
    <input type="checkbox" name="checkContextSizeMedium">
  </span>
  <span class="check-input secondary lg">
    <input type="checkbox" name="checkContextSizeLarge">
  </span>
    <span class="vr mx-md"></span>
  <span class="check-input secondary sm">
    <input type="radio" name="radioContextSize">
  </span>
  <span class="check-input secondary">
    <input type="radio" name="radioContextSize">
  </span>
  <span class="check-input secondary lg">
    <input type="radio" name="radioContextSize">
  </span>
    <span class="vr mx-md"></span>

## Accessibility

Checks are native inputs, so their role, their state, and their keyboard interaction come from the browser. The markup around them still has to provide the name of each control and of each group.

### Grouping related controls

Wrap related options in a `<fieldset>` with a `<legend>`, so assistive technologies announce the question together with each option:

```html
<fieldset>
  <legend>Choose your delivery preferences:</legend>
  <div class="form-check">
    <input class="check-input" type="checkbox" id="optEmail">
    <label for="optEmail">Email notifications</label>
  </div>
  <div class="form-check">
    <input class="check-input" type="checkbox" id="optSMS">
    <label for="optSMS">SMS notifications</label>
  </div>
</fieldset>
```

### Focus visibility

A focused input shows the focus ring on `:focus-visible`. Keep it: keyboard users rely on it to follow their position in a form.

### State communication

The checked and the indeterminate state each show an icon in addition to a change of color, so the state does not depend on color alone. A control without a visible label needs `aria-label` or `aria-labelledby` for its accessible name.

See [forms accessibility]([[docsref:/forms/overview/#accessibility]]) for the guidance that applies to all form controls.
