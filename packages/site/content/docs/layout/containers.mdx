`.container` applies `width: 100%`, the page margin as `padding-inline`, and `margin-inline: auto` to create a centered, padded wrapper. Containers can be nested, though most layouts require only one.

## Available containers

Container classes differ only in when `max-width` takes effect:

- `.container` — applies a `max-width` at each breakpoint
- `.container.{breakpoint}` — `width: 100%` until the named breakpoint, then applies `max-width` for that breakpoint and wider
- `.container.fluid` — `width: 100%` at all breakpoints; no `max-width` cap

## Default container

`.container` is full-width below the `sm` breakpoint and gains a fixed `max-width` at each wider breakpoint.

```html
<div class="container">
  ...
</div>
```

## Responsive containers

Each responsive variant is `width: 100%` below its named breakpoint, then applies `max-width` for that breakpoint and wider. For example, `.container.sm` is full-width below the `sm` breakpoint and scales up through `md`, `lg`, `xl`, and `2xl`. See [Breakpoints]([[docsref:/layout/breakpoints]]) for the pixel values at each breakpoint.

```html
<div class="container sm">...</div>
<div class="container md">...</div>
<div class="container lg">...</div>
<div class="container xl">...</div>
<div class="container 2xl">...</div>
```

## Fluid containers

`.container.fluid` is `width: 100%` at every breakpoint with no `max-width` cap.

```html
<div class="container fluid">
  ...
</div>
```

## Padding

The inline padding of a container is the page margin: `--cx-container-padding`, declared on `:root` per breakpoint from the margin tokens. It is a value of its own and does not follow the [gutter]([[docsref:/layout/gutters]]) of the grid, so the margin of the page and the gap between columns can differ, as they do in a Figma layout grid.

<CxTable>
|  | xs | sm | md | lg | xl | 2xl |
| --- | --- | --- | --- | --- | --- | --- |
| Page margin | {sassVars('margin').xs} | {sassVars('margin').sm} | {sassVars('margin').md} | {sassVars('margin').lg} | {sassVars('margin').xl} | {sassVars('margin')['2xl']} |
</CxTable>

`.px-0` removes the padding of one container, for content that runs to the edges of the viewport. Other [padding utilities]([[docsref:/utilities/padding]]) replace it.

```html
<div class="container fluid px-0">
  ...
</div>
```

`--cx-container-padding` set on an element changes the padding of the containers inside it:

```html
<main style="--cx-container-padding: 2rem;">
  <div class="container">...</div>
</main>
```

<Callout type="warning">
Until v0.6.0 the padding was half of `--cx-gutter-x`, the gutter of the flexbox grid. As of v0.7.0 a `--cx-gutter-x` set on a container no longer changes its padding: set `--cx-container-padding` to the padding itself, half of the old value.
</Callout>

Container classes are generated from `$container-max-widths` and can be disabled by setting `$enable-container-classes: false`.

### Sass maps

Override `$container-max-widths` before importing Chassis CSS to change the `max-width` at each breakpoint.

<ScssDocs name="container-max-widths" file="scss/config/_defaults.scss" />

`$container-paddings` holds the padding of each breakpoint. Set every key to `0` for containers with no padding.

<ScssDocs name="container-paddings" file="scss/config/_defaults.scss" />

`$container-padding-x` was removed in v0.7.0. Set `$container-paddings` instead, with half of the old value at every breakpoint.

### Sass mixins

`make-container()` applies the same base styles as `.container` — `width: 100%`, the padding of `--cx-container-padding`, and centered margins — without the breakpoint `max-width` overrides.

<ScssDocs name="make-container" file="scss/mixins/_grid.scss" />

Apply it in a custom selector to build a container without using the `.container` class:

```scss
.custom-container {
  @include make-container();
}
```
