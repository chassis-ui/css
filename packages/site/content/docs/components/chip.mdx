## Introduction

Chips are compact elements that represent a discrete piece of information, such as a filter, a tag, or a selection. They share the states and style variants of buttons, take their sizes from the chip design tokens, and can hold an icon, an avatar, and a remove button. The optional Chip plugin adds toggling and dismissal.

## Basic structure

Apply `.chip` to an element. The class sets the layout, typography, padding, radius, and interactive states; alone it renders a chip on the body colors, and a context class such as `.default` or `.primary` sets its color.

<Example class="button-examples" code={`<span class="chip">Foundation class</span>
<span class="chip default">Default chip</span>
<span class="chip primary">Primary chip</span>`} />

### Element compatibility

Chips are usually `<span>` elements, and the `.chip` class also applies to `<div>`, `<button>`, and `<a>` elements. Use a `<button>` or an `<a>` for a chip that responds to interaction.

<Callout type="info">
  <strong>Accessibility:</strong> Add `role="button"` to an `<a>` chip that triggers in-page functionality instead of navigating, so assistive technologies announce it as a button.
</Callout>

<Example class="button-examples" code={`<span class="chip primary">Span</span>
<div class="chip primary">Div</div>
<button class="chip primary" type="button">Button</button>
<a class="chip primary" href="#">Link</a>`} />

## Color variants

Add a context class to `.chip` to color it. A chip without a style modifier is solid.

<Example class="button-examples" code={getData('context-colors').map((contextColor) => `<span class="chip ${contextColor.name}">${contextColor.title}</span>`)} />

<Callout name="warning-color-assistive-technologies" />

### Outline style

The `.outline` modifier renders a chip with a border and a transparent background in the colors of its context.

<Example class="button-examples" code={getData('context-colors').map((contextColor) => `<span class="chip ${contextColor.name} outline">${contextColor.title}</span>`)} />

<Callout>
  Some outline variants use a light foreground color and need a dark background to keep enough contrast.
</Callout>

### Smooth style

The `.smooth` modifier renders a chip with a subdued background in the colors of its context, which suits less prominent tags and filters.

<Example class="button-examples" code={getData('context-colors').map((contextColor) => `<span class="chip ${contextColor.name} smooth">${contextColor.title}</span>`)} />

## Icons

Place an icon before or after the chip text. Both SVG icons and icon fonts work.

<Example class="button-examples" code={`<span class="chip default">
    <Icon name="info-circle-solid" role="img" />
    <span>Default</span>
  </span>
  <span class="chip primary">
    <Icon name="info-circle-solid" role="img" />
    <span>Primary</span>
  </span>
  <span class="chip default">
    <span>Default</span>
    <Icon name="info-circle-solid" font />
  </span>
  <span class="chip primary">
    <span>Primary</span>
    <Icon name="info-circle-solid" font />
  </span>`} />

<Callout type="warning">
  Icon spacing relies on the `:first-child` and `:last-child` pseudo-classes. Wrap the chip text in a `<span>` element so the icon is matched as the first or last child.
</Callout>

## Dismissible chips

Add a `.close-button` inside a chip as its remove button. It takes the foreground color of the chip, and with `data-cx-dismiss="chip"` the Chip plugin removes the chip on click. Give the button an `aria-label`, since it has no text.

<Example class="button-examples" code={`<span class="chip default">
    Default
    <button type="button" class="close-button" data-cx-dismiss="chip" aria-label="Remove"></button>
  </span>
  <span class="chip primary">
    Primary
    <button type="button" class="close-button" data-cx-dismiss="chip" aria-label="Remove"></button>
  </span>
`} />

## Disabled chips

Add the `disabled` attribute to a `<button>` chip, or the `.disabled` class to any other element, to disable it. A disabled chip takes the disabled colors and has `pointer-events: none`, so its hover and press states do not trigger.

## Toggle functionality

Add `data-cx-toggle="chip"` to make a chip a selection control. Each click toggles the `.active` class and keeps `aria-pressed` in sync. For a chip that starts selected, add both the `.active` class and `aria-pressed="true"`.

<Example class="button-examples" code={`<!-- Buttons -->
  <p class="d-inline-flex gap-xs">
    <button type="button" class="chip default" data-cx-toggle="chip" aria-pressed="false">Toggle button</button>
    <button type="button" class="chip default active" data-cx-toggle="chip" aria-pressed="true">Active toggle</button>
    <button type="button" class="chip default" disabled data-cx-toggle="chip" aria-pressed="false">Disabled toggle</button>
    <button type="button" class="chip default active" disabled data-cx-toggle="chip" aria-pressed="true">Disabled active</button>
  </p>
  <!-- Links -->
  <p class="d-inline-flex gap-xs">
    <a href="#" class="chip primary" role="button" data-cx-toggle="chip" aria-pressed="false">Toggle link</a>
    <a href="#" class="chip primary active" role="button" data-cx-toggle="chip" aria-pressed="true">Active toggle</a>
    <a href="#" class="chip primary disabled" aria-disabled="true" role="button" data-cx-toggle="chip" aria-pressed="false">Disabled toggle</a>
    <a href="#" class="chip primary active disabled" aria-disabled="true" role="button" data-cx-toggle="chip" aria-pressed="true">Disabled active</a>
  </p>`} />

## JavaScript API

The Chip plugin toggles and dismisses chips, and fires events for both. Chassis JS ships as an ES module — import the `Chip` class:

```js
import { Chip } from '@chassis-ui/css'
```

### Triggers

The data-attribute API needs no JavaScript beyond the plugin itself. A click on a chip with `data-cx-toggle="chip"` toggles it, as shown in [Toggle functionality](#toggle-functionality), and `data-cx-dismiss="chip"` on a button removes the chip.

<JsDismiss name="chip" event="close" />

### Initialization

For programmatic access — calling methods or listening to events — create an instance of each element with the `Chip` class:

```js
const chips = [...document.querySelectorAll('.chip')]
  .map(element => new Chip(element))
```

### Methods

The plugin exposes instance methods for toggling and dismissal, next to the methods every Chassis plugin has:

<CxTable>
| Method | Description |
| --- | --- |
| `toggle` | Toggles the `.active` class of the chip and sets `aria-pressed` to match. |
| `close` | Removes the chip from the DOM and disposes the instance. |
| `dispose` | Destroys the instance and removes its stored data from the element. |
| `getInstance` | Static — returns the instance bound to a DOM element, or `null`: `Chip.getInstance(element)`. |
| `getOrCreateInstance` | Static — returns the instance bound to a DOM element, or creates one: `Chip.getOrCreateInstance(element)`. |
</CxTable>

`getOrCreateInstance` acts on a set of chips without tracking their instances:

```js
// Deselect every selected chip
document.querySelectorAll('.chip.active').forEach(element => {
  Chip.getOrCreateInstance(element).toggle()
})

// Remove every chip with a given tag
document.querySelectorAll('.chip[data-tag="outdated"]').forEach(element => {
  Chip.getOrCreateInstance(element).close()
})
```

### Events

Both events fire on the `.chip` element and bubble:

<CxTable>
| Event | Description |
| --- | --- |
| `toggle.cx.chip` | Fires after the chip is toggled. The `active` property of the event holds the new state. |
| `close.cx.chip` | Fires when the `close` method is called, before the chip is removed. Calling `event.preventDefault()` keeps the chip. |
</CxTable>

```js
const myChip = document.getElementById('myChip')

myChip.addEventListener('toggle.cx.chip', event => {
  console.log(`Chip toggled to ${event.active ? 'active' : 'inactive'} state`)
})

// Move focus before the chip leaves the DOM
myChip.addEventListener('close.cx.chip', () => {
  document.getElementById('chipContainer').focus()
})
```
