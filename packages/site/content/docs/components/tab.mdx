## Introduction

The Tab plugin turns a [nav]([[docsref:/components/nav]]), such as `.nav-tabs` or `.nav-segments`, or a [list]([[docsref:/components/list#javascript-api]]) into a tabbed interface. Each control with `data-cx-toggle="tab"` shows the `.tab-pane` it targets and hides the pane of the control that was active before.

The `.tab-content` wrapper hides every `.tab-pane` child except the one with `.active`. The plugin moves `.active` between the controls and their panes, updates `aria-selected` and `tabindex` on the controls, and handles the arrow keys.

## Basic structure

Add `data-cx-toggle="tab"` to each control and point it at a pane with `data-cx-target`. Wrap the panes in `.tab-content`, give each `.tab-pane` the `id` its control targets, and mark the initial control and its pane with `.active`.

    </li>
    <li class="nav-item" role="none">
      <button class="nav-link" id="profile-tab" data-cx-toggle="tab" data-cx-target="#profile-tab-pane" type="button" role="tab" aria-controls="profile-tab-pane" aria-selected="false">Profile</button>

## Custom markup

The plugin does not require `<ul>` markup: any element with `.nav` or `role="tablist"` can hold the tabs. Do not add `role="tablist"` to a `<nav>` element, since that overrides its native role as a navigation landmark. Place the tab list on an inner element instead, a `<div>` in this example, and wrap the `<nav>` around it.

<Example class="vstack gap-md" code={`<nav aria-label="Tab navigation">
    <div class="nav nav-tabs" id="nav-tab2" role="tablist">
      <button class="nav-link active" id="nav-home-tab2" data-cx-toggle="tab" data-cx-target="#nav-home2" type="button" role="tab" aria-controls="nav-home2" aria-selected="true">Home</button>
      <button class="nav-link" id="nav-profile-tab2" data-cx-toggle="tab" data-cx-target="#nav-profile2" type="button" role="tab" aria-controls="nav-profile2" aria-selected="false">Profile</button>

## Lists

The plugin also works with [lists]([[docsref:/components/list]]). Add `data-cx-toggle="tab"` to each `.list-item` and pair it with a `.tab-pane`; an anchor targets its pane with `href`. The plugin finds the tab list by its `.list` class, as it finds a `.nav`.

## Fade transition

Add `.fade` to each `.tab-pane` to fade the panes in. The initially active pane also needs `.show`, which makes its content visible when the page loads.

```html
<div class="tab-content">
  <div class="tab-pane fade show active" id="home" role="tabpanel" aria-labelledby="home-tab" tabindex="0">...</div>
  <div class="tab-pane fade" id="profile" role="tabpanel" aria-labelledby="profile-tab" tabindex="0">...</div>
  <div class="tab-pane fade" id="messages" role="tabpanel" aria-labelledby="messages-tab" tabindex="0">...</div>
  <div class="tab-pane fade" id="settings" role="tabpanel" aria-labelledby="settings-tab" tabindex="0">...</div>
</div>
```

## Accessibility

Tabbed interfaces follow the [ARIA Authoring Practices Guide tabs pattern](https://www.w3.org/WAI/ARIA/apg/patterns/tabpanel/): `role="tablist"` on the container, `role="tab"` and `aria-selected` on each control, and `role="tabpanel"` on each pane convey the structure and the current state to assistive technologies. Use `<button>` elements for the tabs, since they trigger a change in the page rather than navigate to another one.

### ARIA attributes

When a tab is initialized, the plugin adds the roles that are missing from the markup: `role="tablist"` on the container, `role="tab"` on each control, `role="none"` on the `.nav-item` or `.list-item` around a control, and `role="tabpanel"` on each pane, with `aria-labelledby` when the control has an `id`. It sets `aria-selected` on every control and keeps it in sync as the active tab changes.

The plugin does not set `aria-controls`. Write it in the markup, together with the roles, so the attributes are present before the plugin runs.

### Keyboard interaction

Only the active tab is in the tab order: the plugin sets `tabindex="-1"` on the inactive tabs and updates this [roving `tabindex`](https://www.w3.org/WAI/ARIA/apg/practices/keyboard-interface/) as the active tab changes. With focus on a tab, the arrow keys activate the previous or next tab and wrap around at the ends, and <kbd>Home</kbd> and <kbd>End</kbd> activate the first and last tab. Disabled tabs are skipped.

The plugin does not distinguish horizontal from vertical tab lists: the up and left arrow keys both go to the previous tab, and the down and right arrow keys both go to the next one.

<Callout type="warning">
Make each tab panel focusable with `tabindex="0"`, unless the first element with meaningful content inside the panel is already focusable. The plugin does not add this attribute.
</Callout>

<Callout type="danger">
The Tab plugin **does not** support tabbed interfaces that contain menus. The trigger of the displayed tab is not visible while it sits inside a closed menu, and no standard WAI-ARIA pattern maps this structure for users of assistive technologies.
</Callout>

## JavaScript API

The Tab plugin activates tabs, shows their panes, and fires events around each change. Import the `Tab` class from the Chassis module:

```js
import { Tab } from '@chassis-ui/css'
```

### Triggers

The data-attribute API activates a tab on click without any JavaScript on the page beyond the bundled plugin. Add `data-cx-toggle="tab"` to each control:

<CxTable>
| Attribute | Description |
| --- | --- |
| `data-cx-toggle="tab"` | Activates tab navigation on the control. |
| `data-cx-target` | CSS selector of the `.tab-pane` to show. An anchor can use `href` instead. |
</CxTable>

```html
<!-- Nav tabs -->
<ul class="nav nav-tabs" id="myTab" role="tablist">
  <li class="nav-item" role="none">
    <button class="nav-link active" id="home-tab" data-cx-toggle="tab" data-cx-target="#home" type="button" role="tab" aria-controls="home" aria-selected="true">Home</button>
  </li>
  <li class="nav-item" role="none">
    <button class="nav-link" id="profile-tab" data-cx-toggle="tab" data-cx-target="#profile" type="button" role="tab" aria-controls="profile" aria-selected="false">Profile</button>
  </li>
  <li class="nav-item" role="none">
    <button class="nav-link" id="messages-tab" data-cx-toggle="tab" data-cx-target="#messages" type="button" role="tab" aria-controls="messages" aria-selected="false">Messages</button>
  </li>
  <li class="nav-item" role="none">
    <button class="nav-link" id="settings-tab" data-cx-toggle="tab" data-cx-target="#settings" type="button" role="tab" aria-controls="settings" aria-selected="false">Settings</button>
  </li>
</ul>

<!-- Tab panes -->
<div class="tab-content">
  <div class="tab-pane active" id="home" role="tabpanel" aria-labelledby="home-tab" tabindex="0">...</div>
  <div class="tab-pane" id="profile" role="tabpanel" aria-labelledby="profile-tab" tabindex="0">...</div>
  <div class="tab-pane" id="messages" role="tabpanel" aria-labelledby="messages-tab" tabindex="0">...</div>
  <div class="tab-pane" id="settings" role="tabpanel" aria-labelledby="settings-tab" tabindex="0">...</div>
</div>
```

### Initialization

Each control is its own instance, and the plugin takes no options. For controls without `data-cx-toggle="tab"`, create an instance per control with the `Tab` class and call `show()` on click:

```js
const triggerTabList = document.querySelectorAll('#myTab button')
triggerTabList.forEach(triggerEl => {
  const tabTrigger = new Tab(triggerEl)

  triggerEl.addEventListener('click', event => {
    event.preventDefault()
    tabTrigger.show()
  })
})
```

Activate a single tab through its instance:

```js
const triggerEl = document.querySelector('#myTab button[data-cx-target="#profile"]')
Tab.getOrCreateInstance(triggerEl).show() // Select tab by target

const triggerFirstTabEl = document.querySelector('#myTab li:first-child button')
Tab.getOrCreateInstance(triggerFirstTabEl).show() // Select first tab
```

### Methods

The plugin exposes two instance methods and two static lookup methods for programmatic control:

<Callout name="danger-async-methods" type="danger" />

<CxTable>
| Method | Description |
| --- | --- |
| `dispose` | Destroys the instance and removes stored data from the element. |
| `getInstance` | *Static* — returns the existing instance bound to a DOM element, or `null`. Example: `Tab.getInstance(element)` |
| `getOrCreateInstance` | *Static* — returns the existing instance or creates one. Example: `Tab.getOrCreateInstance(element)` |
| `show` | Activates the tab and shows its pane. The tab that was active before is deactivated and its pane is hidden. Returns before the pane is shown; listen for `shown.cx.tab` for completion. |
</CxTable>

### Events

Showing a tab fires four events, in this order:

1. `hide.cx.tab` (on the current active tab)
2. `show.cx.tab` (on the tab to be shown)
3. `hidden.cx.tab` (on the previous active tab, the same one as for the `hide.cx.tab` event)
4. `shown.cx.tab` (on the newly active tab, the same one as for the `show.cx.tab` event)

When no tab is active yet, `hide.cx.tab` and `hidden.cx.tab` do not fire. Calling `event.preventDefault()` on `hide.cx.tab` or `show.cx.tab` cancels the change.

<CxTable>
| Event | Description |
| --- | --- |
| `hide.cx.tab` | Fired when a new tab is about to be shown, before the current active tab is hidden. `event.target` is the current active tab and `event.relatedTarget` the tab to be shown. |
| `hidden.cx.tab` | Fired after the previous active tab is hidden. `event.target` is the previous active tab and `event.relatedTarget` the new active tab. |
| `show.cx.tab` | Fired when a tab is about to be shown. `event.target` is the tab to be shown and `event.relatedTarget` the current active tab, if there is one. |
| `shown.cx.tab` | Fired after a tab is shown. `event.target` is the new active tab and `event.relatedTarget` the previous active tab, if there is one. |
</CxTable>

```js
const tabEl = document.querySelector('button[data-cx-toggle="tab"]')
tabEl.addEventListener('shown.cx.tab', event => {
  event.target // newly activated tab
  event.relatedTarget // previous active tab
})
```
