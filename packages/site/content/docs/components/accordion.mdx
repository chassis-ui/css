## Introduction

Accordions stack collapsible items built on the native `<details>` and `<summary>` elements. The browser expands and collapses each item, handles keyboard interaction, and exposes the expanded state to assistive technology, so the component works without JavaScript. The `.accordion` class on the wrapper styles the items, and the optional `data-cx-accordion` attribute adds height and caret transitions through the Accordion plugin.

## Basic structure

Wrap `<details>` elements in an `.accordion` element. Each item holds a `<summary>` with an `.accordion-title` and an `.accordion-body` for the content. Items that share a `name` attribute form a group in which only one item is open at a time, and the `open` attribute renders an item expanded on load.

<Example code={`<div class="accordion" data-cx-accordion>
  <details name="example" open>
    <summary>
      <span class="accordion-title">Accordion Item #1</span>
    </summary>
    <div class="accordion-body">
      <p>This is the <b>first item's body</b>, shown by default. It will automatically close when another item is opened by clicking its summary element.</p>
    </div>
  </details>
  <details name="example">
    <summary>
      <span class="accordion-title">Accordion Item #2</span>
    </summary>
    <div class="accordion-body">
      <p>This is the <b>second item's body</b>. It is hidden by default and will open when its summary element is clicked.</p>
    </div>
  </details>
  <details name="example">
    <summary>
      <span class="accordion-title">Accordion Item #3</span>
    </summary>
    <div class="accordion-body">
      <p>This is the <b>third item's body</b>. It is hidden by default and will open when its summary element is clicked.</p>
    </div>
  </details>
</div>`} />

### Headings

The HTML spec permits one heading element as a direct child of `<summary>`, with no ARIA role overrides. Use a heading element as `.accordion-title` when accordion headers need to participate in the document's visual and source-order hierarchy.

### Static items

Items without a `name` attribute, or with a unique one, open and close independently of the others. Grouped and independent items can be mixed in a single accordion.

<Example code={`<div class="accordion" data-cx-accordion>
    <details open>
      <summary>
        <span class="accordion-title">Accordion Item #1</span>
      </summary>
      <div class="accordion-body">
        <p>This is the first item's body, shown by default. Since it has <b>no name attribute</b>, it behaves independently and will only close when its own summary element is clicked.</p>
      </div>
    </details>
    <details name="example-static" open>
      <summary>
        <span class="accordion-title">Accordion Item #2</span>
      </summary>
      <div class="accordion-body">
        <p>This item shares the <b>example-static</b> name attribute with Accordion Item #3, forming a group. It will automatically close when <b>Accordion Item #3</b> is opened.</p>
      </div>
    </details>
    <details name="example-static">
      <summary>
        <span class="accordion-title">Accordion Item #3</span>
      </summary>
      <div class="accordion-body">
        <p>This item shares the <b>example-static</b> name attribute with Accordion Item #2, forming a group. It will automatically close when <b>Accordion Item #2</b> is opened.</p>
      </div>
    </details>
  </div>`} />

## Animation

The `data-cx-accordion` attribute on the wrapper opts the accordion into transitions: the Accordion plugin animates the height of an item as it opens or closes, and the caret and the summary transition with it. Without the attribute the accordion needs no JavaScript: the content opens and closes instantly and the caret does not animate.

## Accessibility

The native `<details>` and `<summary>` elements provide the keyboard interaction, the focus handling and the expanded state of each item without additional JavaScript or ARIA attributes. The `<summary>` is exposed as a disclosure button that <kbd>Enter</kbd> and <kbd>Space</kbd> toggle.

### Heading semantics

A heading placed inside `<summary>` names the disclosure button, but its level is not exposed in the document outline.

```html
<details>
  <summary>
    <h3 class="accordion-title">Accordion Item #1</h3>
  </summary>
  <div class="accordion-body">
    <!-- Content -->
  </div>
</details>
```

Screen readers announce the header as a disclosure button with the heading text as its accessible name, and the browser derives the expanded state from the `open` attribute. Inside a button, heading semantics are absorbed into the button role, so accordion headers are reachable through button and form-control navigation but not through heading shortcuts (the <kbd>H</kbd> key in NVDA, JAWS, or VoiceOver).

When heading-outline navigation is a hard requirement, the [WAI-ARIA APG accordion pattern](https://www.w3.org/WAI/ARIA/apg/patterns/accordion/) uses `<h3><button>` markup that participates in both heading and button navigation, at the cost of abandoning the native `<details>` element and managing the state in JavaScript.

## JavaScript API

The Accordion plugin animates items as they open and close and fires events around each transition. Chassis JS ships as an ES module — import the `Accordion` class:

```js
import { Accordion } from '@chassis-ui/css'
```

### Triggers

The `data-cx-accordion` attribute on the wrapper enables the plugin for its direct `<details>` children. An instance is created for an item, and for the items that share its `name`, on the first click inside it:

```html
<div class="accordion" data-cx-accordion>
  <details name="faq">...</details>
  <details name="faq">...</details>
</div>
```

### Initialization

Each instance belongs to one `<details>` element and watches its `open` attribute. Create the instances up front when items are opened from a script before any click, so that the first change is animated too:

```js
const instances = [...document.querySelectorAll('[data-cx-accordion] > details')]
  .map(element => Accordion.getOrCreateInstance(element))
```

The `open` attribute stays the source of truth: set the `open` property of the `<details>` element to open or close an item, and its instance animates the change.

```js
document.querySelector('#shippingItem').open = true
```

### Methods

The plugin exposes methods to manage the instance of an item:

<CxTable>
| Method | Description |
| --- | --- |
| `dispose` | Destroys the instance and stops watching the `open` attribute. |
| `getInstance` | Static — returns the instance bound to a `<details>` element, or `null`. |
| `getOrCreateInstance` | Static — returns the instance bound to a `<details>` element, or creates one. |
</CxTable>

### Events

All events fire on the `<details>` element. The browser has already toggled the item when `open.cx.accordion` or `close.cx.accordion` fires, so calling `event.preventDefault()` on one of them skips the transition and the event that follows it, but does not revert the state.

<CxTable>
| Event | Description |
| --- | --- |
| `open.cx.accordion` | Fires when an item starts to open. |
| `opened.cx.accordion` | Fires when the opening transition has ended. |
| `close.cx.accordion` | Fires when an item starts to close. |
| `closed.cx.accordion` | Fires when the closing transition has ended. |
</CxTable>

```js
const item = document.querySelector('#shippingItem')

item.addEventListener('opened.cx.accordion', () => {
  // The item is fully expanded
})
```
