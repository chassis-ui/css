## Dark mode

Chassis CSS has two color modes, light and dark. Every color token carries both values, and the mode decides which one is used:

- With no attribute, the page follows the system preference of the visitor.
- `data-cx-theme="light"` or `data-cx-theme="dark"` sets the mode of an element and of everything inside it: on the `<html>` element for the whole page, or on a single component. The nearest attribute wins.

Tailwind CSS projects using [the Tailwind entry point]([[docsref:/getting-started/tailwind]]) get `dark:` and `light:` variants that follow the same rule, on every utility. In the native build, the [`dark:` classes of the utility API]([[docsref:/utilities/api#dark]]) follow the system preference only.

## Example

For example, to change the color mode of a dropdown menu, add `data-cx-theme="light"` or `data-cx-theme="dark"` to the parent `.dropdown`. Now, no matter the global color mode, these dropdowns will display with the specified theme value.

## How it works

- Every color token is written once on `:root`, with its light and its dark value in the CSS `light-dark()` function. The `color-scheme` property picks the value: `:root` declares `light dark`, which follows the system preference, and the attribute sets one of the two.

  ```css
  :root {
    color-scheme: light dark;
    --cx-default-bg-main: light-dark(oklch(100% 0 none), oklch(18.49% 0.004 229.03deg));
  }

  [data-cx-theme="dark"] {
    color-scheme: dark;
  }

  [data-cx-theme="light"] {
    color-scheme: light;
  }
  ```

- `color-scheme` is inherited, so the attribute works on any element. On the `<html>` element it applies to everything; on a component it is scoped to that component, whatever the mode of the page.

- The icons of form controls, such as the caret of a select and the mark of a checkbox, are SVG images with their color written in, which `light-dark()` cannot reach. Chassis declares them once per mode: the light ones on `:root`, the dark ones for `data-cx-theme="dark"` and for a dark system preference.

- The dark values are Sass variables of their own, in `scss/tokens/_colors-dark.scss`, next to the light ones in `scss/tokens/_colors.scss`. Both read the design tokens.

## Usage

### Enable dark mode

Dark mode needs no setup: a page with no attribute is dark for a visitor whose system prefers dark. To show one mode whatever the system prefers, add `data-cx-theme="dark"` or `data-cx-theme="light"` to the `<html>` element. It applies to all components and elements, other than those with a `data-cx-theme` attribute of their own. Building on the [Quick Start template]([[docsref:/getting-started/quick-start]]):

```html
<!doctype html>
<html lang="en" data-cx-theme="dark">
  <head>
    <meta charset="utf-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <title>Chassis CSS demo</title>
    <link href="[[config:cdn.css]]" rel="stylesheet" integrity="[[config:cdn.cssHash]]" crossorigin="anonymous">
  </head>
  <body>
    <h1>Hello, world!</h1>
    <script src="[[config:cdn.jsBundle]]" integrity="[[config:cdn.jsBundleHash]]" crossorigin="anonymous"></script>
  </body>
</html>
```

Chassis CSS does not yet ship with a built-in color mode picker, but you can use the one from the Chassis documentation. [Learn more in the JavaScript section.](#javascript)

### Building with Sass

Disable dark mode entirely by setting `$enable-dark-mode` to `false`. Every color token then has its light value alone, the dark icons of form controls are left out, and `data-cx-theme="dark"` changes nothing.

```scss
@use "@chassis-ui/css/scss/config" with (
  $enable-dark-mode: false
);
@use "@chassis-ui/css/scss/chassis";
```

For a color of your own, write `light-dark()` or use a token of the framework, and it follows the mode like every other color. For anything else that differs between the modes, such as an image, use the `color-mode()` mixin inside the rule of the element. Its styles follow the same rule as the colors: the nearest `data-cx-theme`, and the system preference where no attribute is set.

```scss
@use "@chassis-ui/css/scss/mixins" as *;

.logo {
  background-image: url("logo.svg");

  @include color-mode(dark) {
    background-image: url("logo-dark.svg");
  }
}
```

Outputs to:

```css
.logo {
  background-image: url("logo.svg");
}
.logo[data-cx-theme=dark],
.logo:where([data-cx-theme=dark] *):not(:where([data-cx-theme=dark] [data-cx-theme=light] *)) {
  background-image: url("logo-dark.svg");
}

@media (prefers-color-scheme: dark) {
  .logo:not(:where([data-cx-theme=light], [data-cx-theme=light] *)) {
    background-image: url("logo-dark.svg");
  }
}
```

The selectors look one theme up: an element in a dark theme, inside a light theme, inside another dark theme does not get the dark styles.

Outside a rule, the mixin cannot name the element, so it writes its content under the theme and under the root of a page that follows the system preference. A light theme inside such a dark page then needs the light styles declared as well, with `color-mode(light)`.

```scss
@use "@chassis-ui/css/scss/mixins" as *;

@include color-mode(dark) {
  .logo {
    background-image: url("logo-dark.svg");
  }
}
```

Outputs to:

```css
[data-cx-theme=dark] .logo {
  background-image: url("logo-dark.svg");
}

@media (prefers-color-scheme: dark) {
  :root:where(:not([data-cx-theme=light])) .logo {
    background-image: url("logo-dark.svg");
  }
}
```

The `$color-mode-type` variable sets what the mixin follows. It changes the mixin only: the colors of the framework always follow both the attribute and the system preference.

<CxTable class="table table-options">
| Value | The styles of `color-mode()` follow |
| --- | --- |
| `auto` (default) | The `data-cx-theme` attribute and the system preference, as the colors do. |
| `data` | The `data-cx-theme` attribute only. |
| `media-query` | The `prefers-color-scheme` media query only. |
</CxTable>

With `data`, call the mixin outside a rule:

```scss
@use "@chassis-ui/css/scss/config" with (
  $color-mode-type: data
);
@use "@chassis-ui/css/scss/mixins" as *;

@include color-mode(dark) {
  .logo {
    background-image: url("logo-dark.svg");
  }
}
```

Outputs to:

```css
[data-cx-theme=dark] .logo {
  background-image: url("logo-dark.svg");
}
```

And when setting to `media-query`:

```scss
@use "@chassis-ui/css/scss/config" with (
  $color-mode-type: media-query
);
@use "@chassis-ui/css/scss/mixins" as *;

@include color-mode(dark) {
  .logo {
    background-image: url("logo-dark.svg");
  }
}
```

Outputs to:

```css
@media (prefers-color-scheme: dark) {
  .logo {
    background-image: url("logo-dark.svg");
  }
}
```

## Custom color modes

While the primary use case for color modes is light and dark mode, custom color modes are also possible. Create your own `data-cx-theme` selector with a custom value as the name of your color mode, then declare the CSS variables that the theme changes.

For example, you can create a theme on the primary color with the selector `data-cx-theme="primary"`. In your custom Sass or CSS file, add the new selector with up to four kinds of declarations:

- **`color-scheme`** — every color token has a light and a dark value. Set `color-scheme` to `light` or `dark` to choose the value of every token that the theme leaves alone.
- **Tokens** — the colors of a context, such as `--cx-default-bg-main` of the body context or `--cx-primary-fg-main`. Forms, menus, tables and every component with a context class read them.
- **Body colors** — `--cx-bg-main`, `--cx-fg-main` and the other body colors are resolved from the tokens of the body context on `:root`. On any other element, declare the ones whose token the theme changed again, so that they follow inside the theme. A theme on the `<html>` element needs no such declaration.
- **Component variables** — such as `--cx-menu-bg-color`, where a component needs a value of its own.

```html
  ...
</div>
```

## CSS

### Variables

`:root` declares every color token once, with its light and its dark value in `light-dark()`; no variable is repeated for dark mode. Only the icons of form controls are declared once per mode. [Custom color modes](#custom-color-modes) lists what a theme of your own declares.

### Sass variables

The dark values come from the Sass variables of `scss/tokens/_colors-dark.scss`, which the maps of `scss/maps/_colors-dark.scss` collect. `$enable-dark-mode` and `$color-mode-type` are in `scss/config/_settings.scss`.

### Sass mixins

The `color-mode()` mixin applies your own styles to the light mode, the dark mode or a theme of your own. See the [Sass usage section](#building-with-sass) for more details.
